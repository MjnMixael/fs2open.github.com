Checkpoint Options

Opens via Editors › Mission Specs › Checkpoints.

Mission-wide settings for the in-engine checkpoint system. A checkpoint saves the state of a mission in progress — ship damage, subsystems, weapons, positions, wing waves, SEXP variables, score and mission time — so the player can resume from it later, including after quitting the game.

Checkpoints are written by the store-checkpoint operator, so a mission that never calls it has none. These settings control what happens around that.

Availability

ControlDescription
Disallow checkpoints in campaign modeEvery checkpoint operator does nothing while this mission is flown as part of a campaign, and no resume prompt appears.
Disallow checkpoints in simulator modeThe same, for when the mission is flown outside a campaign — from the mission simulator, or launched directly.

These are separate switches because the two contexts often want different behavior: a checkpoint is a courtesy during a long campaign mission, but it can undermine a mission being replayed for score. Checking both switches checkpoints off entirely for this mission.

Resuming

When a usable checkpoint exists, the engine asks the player whether to resume on the way into the mission — after the briefing and loadout, before the first frame, with no second loading screen. These settings control that prompt.

ControlDescription
Do not offer to resume on mission entrySuppresses the automatic prompt. The checkpoint still exists and load-checkpoint still works; use this for missions where a scripted mid-mission prompt is the intended flow.
Keep the player's briefing loadout when resumingLeaves the player's ship class and weapons as the briefing set them, rather than restoring the ones the checkpoint recorded. Lets the player retry with a different fit.
Keep the player wing's briefing loadout when resumingThe same, for the rest of the player's wing.

The two loadout options apply only to the automatic prompt, which is why they are unavailable once it is suppressed. load-checkpoint and prompt-user-checkpoint-load take the same options as arguments of their own.

Lifetime

ControlDescription
Delete this mission's checkpoints once it is completedDiscards them when the player finishes the mission successfully, so replaying it later starts clean instead of offering a checkpoint from the previous run. A failed mission keeps its checkpoints, since that is exactly when they are wanted.

Without this, checkpoints persist until delete-checkpoint is called or a later store-checkpoint overwrites the slot.

Notes

  • Checkpoints are stored per pilot, per campaign and per mission, so one pilot's checkpoints never appear for another.
  • A checkpoint saved before the mission file was last edited is treated as absent, because the mission's events and variables would no longer line up with it.
  • Checkpoints do nothing in multiplayer.
