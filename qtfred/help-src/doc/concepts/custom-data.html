Custom Data

Custom data attaches arbitrary key-value pairs to a mission, a campaign, or an individual ship. It has no built-in effect on gameplay; it exists to be read by Lua scripts or SEXPs that know to look for specific keys. Values are stored as strings.

Per-ship custom data is saved to the mission file in a $begin_custom_data … $end_custom_data block on the ship. Scripts read a ship's data through the ship object's custom-data methods, and SEXPs such as ship-custom-data-get-int and ship-custom-data-set read and write it during the mission.

Editor-defined schemas

A schema declares the keys an editor is expected to use, along with a type, an optional default, and an optional description. Declaring a schema is optional — without one the dialog treats every entry as a free-form string — but a schema gives the Custom Data dialog type-aware value controls, help text, and reset-to-default support.

Schemas are defined in editor.tbl (or any modular *-edt.tbm), in one section per domain. Sections may appear in any order, and any subset may be present:

#MissionCustomData
	+Key:         music_track
	+Type:        string
	+Default:     Aquitaine
	+Description: Name of the ambient track this mission requests.

	+Key:         intro_seen
	+Type:        bool
	+Default:     false
#End

#CampaignCustomData
	+Key:         starting_credits
	+Type:        int
	+Default:     5000
#End

#ShipCustomData
	+Key:         escort_priority
	+Type:        int
	+Default:     0
	+Description: Higher values are escorted first by allied AI.
#End
FieldRequiredNotes
+Key:YesThe key name.
+Type:Yesstring, int, or bool. An unrecognized type produces a warning and falls back to string.
+Default:NoValue used by the dialog's Reset button, and — for mission keys only — the value seeded into new missions (see below). Omitted defaults are empty.
+Description:NoShown as help text in the dialog when the key is selected.

Mission keys and defaults

When a mission is opened in FRED, any mission-domain key that is not already present in the mission is automatically added with its default value, so the expected entries exist without the designer creating them by hand. Campaign and ship entries are not auto-added; use the dialog's schema assistance to add them where needed.

Scripts can also register mission-domain keys at runtime by calling mn.addDefaultCustomData(key, defaultValue, description). Script-registered keys are always treated as string, and, like all defaults, are a FRED-only convenience that never affects gameplay directly.
